Merchant Center CSV upload errors: check CSV vs TSV first

By Rowvia · Published 22 October 2026 · Official Google guidance checked on this date

If your shop exports a CSV and Merchant Center cannot read the upload, start with the file structure. Changing product descriptions will not repair a separator problem.

This guide covers preparing a tab-delimited product file from a shop export. It does not diagnose your account or guarantee approval.

On this page: File formats · Convert a copy · Shifted rows · Processing results

Does Merchant Center accept CSV or TSV?

Google’s Create a product file guide lists TXT, TSV and XML and describes tab-delimited spreadsheets or XML as the file types. A comma-separated shop export is therefore not automatically ready for that documented file-upload route.

There is a wording nuance: individual attribute pages, including Google’s ID guidance, label some text examples “TSV or CSV.” An attribute example alone does not establish which file your chosen import route accepts. Check the instructions for your actual data source, especially if a platform integration handles submission.

CSV separates fields with commas; TSV uses tabs. Changing catalog.csv to catalog.tsv changes the name, not the content. Export the intended format from a correctly imported working copy.

Convert a working copy to tab-delimited text

Keep the original export privately so you can compare it with your changes. The following is a preparation workflow, not an automatic conversion or a complete feed template:

  1. Import deliberately. In your spreadsheet editor, choose the separator used by the source export. Check that titles and descriptions occupy the intended columns. Preserve identifiers as text so leading zeros are not lost.
  2. Map the header. Use the attribute names required by Google, rather than your shop’s internal column labels. Check the product data specification for the attributes your products and destinations need.
  3. Export the intended sheet. Google’s tab-delimited instructions describe Excel’s Text (tab delimited) TXT option and Google Sheets’ tab-separated download. The same instructions describe a TXT filename for submission; the general file guide also lists TSV. Follow your data-source setup and match its registered filename where applicable.
  4. Inspect the saved text. Confirm that the exported file contains tabs between fields. Check the saved artifact itself; a spreadsheet view can hide an export mistake.

Do not replace every comma with a tab. A comma may belong inside a description or a quoted CSV value. A blind replacement can create extra columns and corrupt your data.

Find extra or missing separators

For tab-delimited files, Google specifies an attribute header, one product per subsequent line, and tabs separating fields. It warns against tabs or line breaks inside attribute values and trailing tabs at line ends. See the format requirements.

This fictional sketch shows a shifted row. The arrow represents a tab; do not put arrows in your upload. These three columns illustrate alignment only and are not a complete product file.

id    → title        → description
SKU-A → Ceramic mug  → Blue glazed mug
SKU-B → Notebook     → Pocket → notebook

The final row has four fields under three headers. Investigate whether the description contains an unintended tab or the export mapping is wrong. Compare the source cell, the header and an intact row before changing anything. Do not delete a product fact just to make the column count match.

Google’s data-source troubleshooting guide identifies extra or missing tabs as a cause of column misalignment. An empty cell can be intentional; check whether its attribute is required before filling it.

After upload, separate parsing from approval

Review the data source’s latest processing results for file and attribute issues. Google says processing checks basic file and data problems; review Products’ “Needs Attention” area for the wider set of issues. The troubleshooting guide explains where to find these reports.

A readable file still needs accurate product information and must meet applicable destination, category, country and policy requirements. Price and availability must reflect the real offer. Use the product data specification for that separate review. Successful parsing does not establish approval.
