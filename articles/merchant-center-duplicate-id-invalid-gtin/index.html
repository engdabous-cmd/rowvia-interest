Duplicate IDs and invalid GTINs: two different Merchant Center fixes

By Rowvia · Published 22 October 2026 · Official Google guidance checked on this date

A repeated offer ID and an invalid GTIN need different investigations. Replacing both with a newly generated number can hide the warning while making the product data less accurate.

Trace the repeated offer ID

Google’s ID guidance requires a unique, stable ID for each different product, including each variant. Do not recycle an old product’s ID or rely on letter case alone for uniqueness. The same product can retain its ID across countries and languages; a repeated string is not enough to diagnose every multi-market dataset.

This fictional extract illustrates a collision within one export context, not a complete product file:

id      | title              | item_group_id
TEE-7   | Cotton tee, small  | TEE-FAMILY
TEE-7   | Cotton tee, medium | TEE-FAMILY

Compare the source records. An export join may have duplicated one record, or two actual variants may share an incorrect ID mapping. Repair the cause and preserve existing correct IDs; do not renumber the whole catalog.

A shared variant group is different

Use item_group_id for a family of actual variants, while each variant keeps its own id. Google’s current item group guidance also specifies a shared item_group_title and variant_option describing the properties that distinguish variants. Retain the applicable standard attributes, such as size and color, alongside variant options. Check the current destination requirements and make the submitted details match the selected landing-page variant.

The three-column sketch above only demonstrates the ID collision. It deliberately omits most feed attributes and is not a compliant variant template. Fixing an ID does not establish full variant compliance.

Check the assigned trade-item identifier

A GTIN identifies the trade item rather than your internal offer record. Google’s GTIN guidance says to submit only a value you know is correct. Some products have no assigned GTIN; do not guess one or change identifier declarations merely to suppress a warning.

Compare the saved value with trustworthy manufacturer or packaging evidence for the exact product and variant. Preserve identifier cells as text and watch for lost leading zeros or scientific notation during spreadsheet imports.

A failed check digit is a clue to investigate transcription or source data. Recomputing the last digit is not evidence of manufacturer assignment. Even a number that passes arithmetic can belong to another item or be unsuitable under other GTIN rules.

Keep unresolved facts unresolved

Record uncertain identifiers for review, repair the source mapping where evidence supports it, and examine Merchant Center’s processing results. Consult the product data specification for remaining requirements. If the file itself is unreadable, start with the CSV vs TSV guide.
